# Controller API Specification

This document describes the WebSocket and HTTP APIs required for the discar iOS app to communicate with the controller (Raspberry Pi or similar).

**Base URL:** `http://{ip}:8000`
**WebSocket:** `ws://{ip}:8000/ws/status`

---

## WebSocket API

The app connects to `/ws/status` for real-time updates. The controller should send JSON messages.

### Message Format

All messages are JSON with a `type` field:

```json
{
  "type": "message_type",
  "data": { ... }
}
```

### Message Types

#### `initial` - Full State Snapshot

Sent immediately when client connects. Contains all system state.

```json
{
  "type": "initial",
  "data": {
    "controller": {
      "ready": true,
      "recording": false,
      "uuid": null,
      "duration": 0
    },
    "cameras": [
      {
        "name": "cam-front",
        "connected": true,
        "state": "idle",
        "segment": null,
        "cpu": 45.2,
        "ram": 32.1,
        "disk_free_gb": 128.5,
        "temp": 52.3,
        "sync_status": "idle",
        "sync_segments_synced": 0,
        "sync_segments_queued": 0
      }
    ],
    "system": {
      "cpu_percent": 23.5,
      "mem_percent": 45.2,
      "temp_c": 48.0
    },
    "can": {
      "connected": true,
      "frame_count": 0,
      "file_size_bytes": 0
    },
    "storage": {
      "healthy": true,
      "logging": {
        "accessible": true,
        "free_gb": 256.0
      },
      "sync": {
        "accessible": true,
        "free_gb": 512.0
      }
    }
  }
}
```

#### `controller` - Controller State Update

```json
{
  "type": "controller",
  "data": {
    "ready": true,
    "recording": true,
    "uuid": "ABC123-DEF456-...",
    "duration": 45
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `ready` | bool | All cameras connected and ready |
| `recording` | bool | Currently recording |
| `uuid` | string? | Session UUID (null when not recording) |
| `duration` | int | Recording duration in seconds |

#### `camera` - Single Camera Update

```json
{
  "type": "camera",
  "data": {
    "name": "cam-front",
    "connected": true,
    "state": "recording",
    "segment": 3,
    "cpu": 67.2,
    "ram": 45.1,
    "disk_free_gb": 120.5,
    "temp": 58.0,
    "sync_status": "syncing",
    "sync_segments_synced": 2,
    "sync_segments_queued": 5
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Camera identifier (e.g., "cam-front", "cam-left") |
| `connected` | bool | Camera is reachable |
| `state` | string | "idle", "recording", "error" |
| `segment` | int? | Current recording segment number |
| `cpu` | double? | CPU usage % |
| `ram` | double? | RAM usage % |
| `disk_free_gb` | double? | Free disk space in GB |
| `temp` | double? | Temperature in Celsius |
| `sync_status` | string? | "idle", "syncing", "complete" |
| `sync_segments_synced` | int? | Segments synced to storage |
| `sync_segments_queued` | int? | Total segments to sync |

#### `cameras` - All Cameras Update

```json
{
  "type": "cameras",
  "data": [
    { "name": "cam-front", ... },
    { "name": "cam-left", ... }
  ]
}
```

#### `system` - System Metrics

```json
{
  "type": "system",
  "data": {
    "cpu_percent": 23.5,
    "mem_percent": 45.2,
    "temp_c": 48.0
  }
}
```

#### `can` - CAN Bus Status

```json
{
  "type": "can",
  "data": {
    "connected": true,
    "frame_count": 15234,
    "file_size_bytes": 524288
  }
}
```

#### `storage` - Storage Status

```json
{
  "type": "storage",
  "data": {
    "healthy": true,
    "logging": {
      "accessible": true,
      "free_gb": 256.0
    },
    "sync": {
      "accessible": true,
      "free_gb": 512.0
    }
  }
}
```

#### `sync` - Sync Progress Update

```json
{
  "type": "sync",
  "data": {
    "camera": "cam-front",
    "synced": 5,
    "queued": 10,
    "status": "syncing"
  }
}
```

#### `ping` - Keep-alive

Server can send ping messages. Client sends WebSocket pings every 25 seconds.

## HTTP REST API

### Recording Control

#### Start Recording

```
POST /api/record/start?uuid={uuid}
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `uuid` | string | Session UUID (generated by phone) |

**Response:** `200 OK` or error

#### Stop Recording

```
POST /api/record/stop
```

**Response:** `200 OK` or error

---

### Status

#### Get Full Status

```
GET /api/status
```

**Response:**
```json
{
  "ready": true,
  "recording": false,
  "uuid": null,
  "duration": 0,
  "cameras": [
    {
      "name": "cam-front",
      "connected": true,
      "state": "idle",
      "segment": null,
      "cpu": 45.2,
      "ram": 32.1,
      "disk_free_gb": 128.5,
      "temp": 52.3
    }
  ]
}
```

#### Get CAN Status

```
GET /api/can/status
```

**Response:**
```json
{
  "connected": true,
  "frame_count": 15234,
  "file_size_bytes": 524288
}
```

#### Get Storage Status

```
GET /api/storage/status
```

**Response:**
```json
{
  "healthy": true,
  "logging": {
    "accessible": true,
    "free_gb": 256.0
  },
  "sync": {
    "accessible": true,
    "free_gb": 512.0
  }
}
```

---

### Storage Management

#### Remount Storage

```
POST /api/storage/remount?mount={mount}
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `mount` | string | "logging", "sync", or "all" |

**Response:** `200 OK` or error

#### Unmount Storage (Eject)

```
POST /api/storage/unmount?mount={mount}
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `mount` | string | "sync" (for safe USB removal) |

**Response:** `200 OK` or error

---

### Phone Sync

#### Upload Phone Session

```
POST /api/sync/phone
Content-Type: multipart/form-data
```

Uploads phone sensor CSV files to controller storage.

**Response:**
```json
{
  "success": true,
  "files_saved": 10
}
```

---

### Logging

#### Send Log Message

```
POST /api/log
Content-Type: application/json
```

**Request:**
```json
{
  "level": "info",
  "category": "recording",
  "message": "Started recording session"
}
```

**Response:** `200 OK`

---

## Update Frequency Recommendations

| Type | Frequency |
|------|-----------|
| `controller` | On state change + every 1s during recording |
| `camera` | Every 2-5s for metrics, immediately on state change |
| `system` | Every 5s |
| `can` | Every 2s during recording |
| `storage` | Every 10s or on change |
| `sync` | During active sync, every 1s |

---

## Error Handling

HTTP errors should return appropriate status codes:
- `400` - Bad request (invalid parameters)
- `404` - Endpoint not found
- `500` - Server error

WebSocket should attempt to stay connected. If connection drops, client will auto-reconnect with exponential backoff.
